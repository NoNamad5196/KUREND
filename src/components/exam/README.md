# B2 · 시험에서 학습 완료까지

기준: `docs/b-split.md` 전체, `docs/IMPLEMENTATION-PLAN.md` §5·§6·§8-8~§8-11·§10.
서비스명은 분담 문서에 따라 KUREND, 캐릭터 이름은 새내기를 사용한다.

## 구현 범위

| 경로 | 동작 |
|---|---|
| `/session/[id]/exam` | 시험 시작, 문항별 SSE 답안·속마음·회상 표시, 저장된 답안 재생, 보기 설정 저장, 자동 진행, 제출 |
| `/session/[id]/result` | 문항별 채점 스트리밍, 성적표, 놓친 곳 목록, 되짚기 또는 바로 완료 |
| `/session/[id]/review` | 자료 발췌·진단·내 설명 비교, 원문 드로어, gap별 튜터 대화, 이해 확인, 완료 |
| `/session/[id]/complete` | 서버 결과·판정·챕터 상태 표시, 재학습 세션 생성, 자료·홈 이동 |

라우트는 Next 15의 비동기 `params`를 읽는 서버 컴포넌트이며, 화면 본체는 `pages/`에 있다.
API 경로에는 base를 붙이지 않는다. 로컬 `.env.local`은 `NEXT_PUBLIC_API_BASE=/api/mock`을 사용한다.

## 복원과 오류 처리

- 진입 시 `useSession`으로 허용 상태를 확인한다. 다른 단계는 공용 `routeForSession`으로 이동한다.
- 시험은 저장된 답안을 복원하고 처음 미작성 문항부터 진행한다. 이미 작성한 문항은 recap을 받아 즉시 표시한다.
- 자동 진행은 서버 저장·스트림 종료·화면 타이핑 완료 후 1초를 기다린다. 오류가 나면 멈춘다.
- `EVALUATING`에서 새로고침하면 `evaluate`를 다시 보내지 않고 결과를 조회한다. 409는 1초 간격으로 최대 60회 더 기다리고 재시도 화면을 표시한다.
- SSE의 `error`, 정상 `done` 없이 끊긴 연결, 저장 이벤트 없는 종료를 구분해 재시도를 제공한다.
- 요청 중 중복 실행을 막으며, 페이지 이동 및 튜터 대상 변경 시 진행 중인 SSE를 abort한다.
- gap 이해 확인과 튜터 응답은 각 필드만 갱신하여 서로의 상태를 덮어쓰지 않는다.
- 완료 판정은 서버의 `finalVerdict`를 사용한다. 되짚었다고 원래 시험 점수나 판정을 다시 계산하지 않는다.

## 통합 후 확인할 시나리오

아래는 **수동 검증 목록이며, 아직 실행 결과가 아니다**. 분담 문서에 따라 B2에서는 `pnpm dev`와 `pnpm build`를 실행하지 않았다.

1. 데모 세션에서 설명을 끝내고 시험 시작 → 속마음 → 답안 타이핑 → 설명 하이라이트를 확인한다.
2. 자동 진행으로 3문항을 작성하고, 안 가르친 문항의 빨간 밑줄과 `못 들은 부분`을 확인한다.
3. 문항 번호·이전·다음으로 저장된 답안을 다시 열어 recap이 중복 없이 즉시 표시되는지 확인한다.
4. 보기 설정 3개를 변경하고 새로고침한다. localStorage가 차단되거나 값이 잘못되어도 기본 설정으로 열린다.
5. 답안 작성 중 연결을 끊고 재시도한다. 저장된 문항은 중복 생성 없이 이어져야 한다.
6. 제출 → 순차 채점 → 성적표를 확인한다. 채점 중 새로고침하면 `POST /evaluate`가 다시 호출되지 않아야 한다.
7. 놓친 곳에서 원문 드로어의 발췌 강조, 빈 설명의 대체 문구, 튜터 프리셋·자유 질문·오류 재시도를 확인한다.
8. `이해했어요 ✓`를 누르면 카드가 접히고 남은 개수가 줄어든다. 모두 확인하면 학습을 마칠 수 있다.
9. gap 0개, 모두 되짚은 경우, 놓친 곳을 남기고 끝낸 경우의 완료 화면을 각각 확인한다. `/session/sess_done/complete`도 확인한다.
10. 같은 목차 다시 가르치기 → 새 세션 준비 화면, 자료로 돌아가기, 홈 이동을 확인한다.
11. 1280×800·390×844에서 가로 스크롤, 키보드 조작, 보기 설정 Escape 닫기, 움직임 줄이기 설정을 확인한다.
