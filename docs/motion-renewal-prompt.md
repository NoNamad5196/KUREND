# 화면별 캐릭터 모션 구현 프롬프트

아래부터 복사해 사용하세요. 이 문서는 구현 지시안이며, 화면별 모션 리뉴얼 자체를 적용한 기록은 아닙니다.

---

KUREND의 현재 main 코드를 먼저 읽고, 새 프론트 디자인에 맞는 화면별 캐릭터 모션을 실제로 구현해줘.
이번 작업은 모션과 상태 표현의 개선이다. 현재 레이아웃·학습 흐름·문구는 유지한다.
서비스의 중심은 “설명하다 보면, 어느새 내 지식.”이다. 졸업은 학습 후의 보상으로 다룬다.

1. 디자인과 자산

- 따뜻한 종이 배경, 짙은 초록, 연두 포인트, 큰 제목, 얇은 구분선에 맞춰 차분하게 움직인다.
- 남학생·여학생·KU의 기존 원본, 의상, 정면·측면·후면 자산을 재사용한다. 새로운 캐릭터로 대체하지 않는다.
- JuniorAvatar, JuniorOrMascot, Mascot, junior-fx, 게임 장면과 실제 호출 화면을 모두 확인한다.
- PNG는 몸 전체 이동·기울임·크기 변화로 표현한다. 분리되지 않은 팔·입이 실제로 움직인다고 가정하지 않는다.
- 선택한 후배가 가르치기→시험→결과→완료까지 이어지게 한다. 일반 안내 Mascot과 선택 가능한 KU 캐릭터의 역할을 혼동하지 않는다.
- 남학생은 조금 빠르고 밝게, 여학생은 작고 정확하게, KU는 한 박자 천천히 반응한다. 성격 표현 때문에 실제 학습 판정을 바꾸지 않는다.

2. 공통 모션 규격

- 버튼·포커스: 150–220ms. 화면 내 요소 등장: 300–450ms. 일회 캐릭터 반응: 450–900ms.
- 기본 이동은 2–8px, 기울임은 2–4도, 스케일 변화는 1–2% 안에서 사용한다.
- 작은 점프는 확정된 만점·완료에서만 1회, 높이는 최대 12px. 컨페티는 최대 8조각, 900ms 안에 제거한다.
- 읽는 중에는 거의 정지한다. 상시 흔들기, 무한 점프, 반복 축하, 화면 전체 흔들기, 큰 광선은 사용하지 않는다.
- 호흡은 필요한 큰 캐릭터 한 명에만 7–9초 주기·0.6% 이하로 적용한다. 목록과 모바일에서는 정적으로 둬도 된다.
- transform/opacity 중심으로 구현하고 새 모션 라이브러리는 실제 필요가 있을 때만 추가한다.
- 기존 전역 page-enter는 opacity만 사용하는 이유가 있다. 상위 transform으로 고정 드로어·오버레이 위치를 깨뜨리지 않는다.

3. 로그인 /login

- 최초 진입: 캐릭터 영역이 아래 8px에서 제자리로 400ms 동안 나타난다. 1회만 재생한다.
- 여러 캐릭터가 있다면 모두가 반복해서 뛰지 않게 하고, 대표 캐릭터만 500ms 작은 인사를 한다.
- Google 버튼 hover/focus에는 화살표 3px 이동만 적용한다. 클릭 후 인증 결과를 모르는 동안 성공 모션을 보여주지 않는다.
- 준비 중·베타·체험 계정 UI를 다시 만들지 않는다.

4. 홈 /

- 소개 캐릭터: 처음 보일 때 450ms 인사 1회, 이후 정지한다.
- 진행 중 후배: 현재 선택된 캐릭터·LIFE·학습 진행을 그대로 사용한다. 이어하기 버튼에 focus가 오면 180ms 동안 2px 기울어지는 정도로 반응한다.
- LIFE가 1이어도 계속 불안하게 떨지 않는다. 정적인 표정과 상태 문구로 알려준다.
- 자료 목록·최근 기록 캐릭터는 정적이다. 홈의 주된 행동은 공부 시작·이어하기다.

5. 온보딩 /onboarding

- 자동 노출은 첫 가입 직후 한 번, 수동 진입은 마이페이지의 “서비스 이용 방법 다시 보기”만 유지한다.
- 1단계 소개: 400ms 등장, 600ms 인사 1회.
- 후배 선택 단계: 선택된 후배만 550ms 끄덕임. 다른 후배는 정지한다.
- 설명 시연 단계: 기존 설명하기 버튼으로 시연 상태가 바뀌면 생각→이해 반응을 총 900ms 이내에 보여준다.
- 마지막 단계: 650ms 작은 반짝임 1회. 버튼은 모션 종료 전에도 사용할 수 있다.
- 이전 단계로 돌아가거나 렌더링이 반복될 때 모든 캐릭터를 다시 재생하지 않는다.

6. 자료 업로드 /new 및 자료 분석 /materials/[id]

- 업로드 전 캐릭터는 정적. 파일 추가 성공 시 450ms 작은 끄덕임 1회.
- 잘못된 확장자·용량 오류는 입력 영역의 텍스트로 안내한다. 캐릭터를 벌주듯 흔들지 않는다.
- 실제 업로드·목차 분석 중에만 책 넘김 또는 말줄임 효과를 사용한다.
- READING/SPLITTING/TITLING은 기존 서버 이벤트에 연결한다. 임의 타이머로 완료 단계나 진행률을 만들지 않는다.
- READY가 확인되면 600ms 한 번 반응하고 종료. 실패·취소·페이지 이탈 시 진행 모션도 종료한다.

7. 후배 선택 /materials/[id]/junior

- 카드 hover와 키보드 focus: 180ms 동안 캐릭터를 3px 올린다. 해제 시 원위치.
- 선택 클릭: 남학생은 500ms 작은 반동, 여학생은 550ms 작은 기울임, KU는 650ms 느린 끄덕임 1회.
- 선택 여부는 테두리·텍스트로 계속 확인 가능해야 한다. 모바일 터치에서도 선택과 확인을 구분할 수 있게 한다.
- 같은 카드를 반복 클릭해 애니메이션이 쌓이지 않게 한다. 후배 변경 시 기존 자료·진도·세션 복구를 유지한다.

8. 학습 준비 /session/[id]/prepare

- 요청 중: 집중 자세와 작은 말줄임만 반복한다.
- ready 이벤트: 650ms 끄덕임과 작은 반짝임 1회, 이후 준비 자세.
- 오류: 모션을 멈추고 기존 재시도 안내를 보여준다. 실패를 성공처럼 연출하지 않는다.
- 일반 챕터와 졸업시험 모두 선택한 후배를 사용한다. 준비 완료 버튼을 모션 때문에 늦추지 않는다.

9. 가르치기 /session/[id]/teach — 상태별 상세

- idle: 거의 정지. 선택적으로 미세 호흡만 사용한다.
- listen: 입력창에 포커스하고 실제 설명을 쓰기 시작할 때 450ms 작은 끄덕임 1회, 이후 집중 자세. 키 입력마다 다시 시작하지 않는다.
- thinking: 설명 POST가 시작될 때 생각 자세·말줄임. 응답·오류·취소 시 종료한다.
- question: 새로운 junior.question의 messageId가 확정될 때 550ms 기울임 1회. 질문을 읽는 동안 정지한다.
- doubt: 새로운 junior.doubt에 650ms 동안 2도 갸웃 1회와 작은 물음표. 화면 흔들림이나 실패 낙인을 주지 않는다.
- understand: 서버가 확정한 목표 커버리지 또는 숙련도가 실제로 증가할 때만 700ms 끄덕임·반짝임 1회.
- 남학생 선택형도 선택한 설명의 실제 전송 상태에 연결한다. 보기 선택 자체를 정답으로 판정하지 않는다.
- KU의 반복 학습은 실제 숙련도 증가에서만 반응한다. 동일 설명 재전송이나 신규 단어 표시만으로 이해 효과를 띄우지 않는다.
- 마지막 질문을 다시 불러오거나 SSE 토큰이 추가될 때 일회 반응을 반복하지 않는다.
- 스트리밍, 자동 스크롤, 설명 임시 복구, 다시 전송, 시험으로 이동 버튼의 기존 동작을 유지한다.

10. 시험 /session/[id]/exam

- 시험 시작 전: 선택한 후배가 차분히 집중한다. 아직 쓰지 않는데 계속 필기하지 않는다.
- 실제 답안 생성 중: 생각→쓰기 상태. PNG는 작은 기울임과 말줄임, SVG의 실제 분리된 연필이 있으면 기존 필기 동작을 재사용한다.
- answer.saved: 350ms 작은 끄덕임 1회. 정답 여부를 아직 모르므로 축하하지 않는다.
- cached 응답이나 이미 저장된 답안 복원에서는 저장 모션을 반복하지 않는다.
- 답안 텍스트는 즉시 표시하고, 모션을 기다리느라 스트리밍이나 다음 문항을 지연시키지 않는다.
- 남학생·여학생·KU의 새 챕터 학습 목표 5개·시험 5문항과 졸업시험 혼합 10문항은 현재 구현을 그대로 유지한다. 이미 저장된 과거 시험의 문항 수는 변경하지 않는다.

11. 채점·결과 /session/[id]/result

- 실제 채점 중에는 조용한 대기 자세와 상태 텍스트를 사용한다.
- 서버 결과 확정 후 통과: 650ms 작은 끄덕임·반짝임 1회.
- 만점: 최대 12px 점프 1회와 작은 컨페티, 전체 900ms 이내.
- 미통과: 600ms 동안 살짝 내려앉았다가 차분한 자세로 복귀. 반복 울음·경고 흔들기는 사용하지 않는다.
- 점수·LIFE·합격 여부는 서버 값만 사용한다. 결과 페이지 재방문으로 LIFE 차감이나 축하를 반복하지 않는다.
- 기존 ApplyLifeResponse.applied, livesBefore→livesAfter와 ResultOverlay/LifeHearts의 시간 관계를 먼저 확인하고 보존한다.
- 결과 텍스트·복습·다음 행동 버튼은 모션 도중에도 읽고 사용할 수 있게 한다.

12. 되짚기 /review 및 오답노트

- 노트 목록과 원문을 읽을 때는 정적 캐릭터를 사용한다.
- 실제 튜터 요청 중에만 생각 자세, 응답 완료 후 500ms 끄덕임 1회.
- 노트 열기·스크롤·원문 드로어 열기 자체에는 성공 효과를 주지 않는다.
- 드로어 이동은 200–250ms 이내. Escape·포커스 복귀와 모바일 화면 고정 위치를 유지한다.

13. 학습 완료 /session/[id]/complete

- 해당 세션의 완료를 새로 확인했을 때만 800ms 작은 축하 1회.
- 결과에서 이미 축하를 봤다면 완료 화면에는 별도 큰 축하를 반복하지 않는다.
- 이후 정지해서 학습 기록·다음 학습·졸업시험 버튼이 중심이 되게 한다.

14. 마이페이지·학습노트·세션 목록·지식 지도·앨범

- 기록 화면의 캐릭터는 정적 이미지가 기본이다.
- 카드 hover/focus는 150–180ms의 작은 색상/화살표 변화만 적용한다.
- 목록 항목 전체의 순차 등장이나 여러 후배의 동시 반복 모션은 사용하지 않는다.
- “서비스 이용 방법 다시 보기”는 기존 온보딩 replay로 연결하며 새 자동 노출 조건을 만들지 않는다.

15. 게임오버 /runs/[id]/game-over

- 서버가 GAME_OVER를 확정했을 때만 장면에 진입한다.
- 기존 남학생 군복·군용트럭/인사, 여학생 멀어지기, KU 작은 트럭 이야기는 보존한다.
- title→lines→wave→leave→quiet→next의 기존 캐릭터별 단계와 건너뛰기를 유지한다.
- 각 단계의 JS 시간과 CSS 이동 시간을 함께 확인해 인사·탑승·출발이 엇갈리지 않게 한다.
- 마지막 상태는 정지하고 새 후배 만나기 버튼에 바로 접근할 수 있게 한다.

16. 졸업 /runs/[id]/graduation

- 졸업 API 성공 후 기존 졸업복 등장→학사모 던지기 1회→요약 순서를 유지한다.
- 학사모를 몇 초마다 계속 던지는 반복은 제거한다. 타이머도 함께 정리한다.
- 요약을 읽는 동안 캐릭터와 장식은 정지한다.
- 졸업 처리를 다시 호출하거나 기존 챕터/졸업시험 완료 판정을 변경하지 않는다.

17. 구현과 검증 조건

- listen/question/understand 등은 기존 데이터에서 계산하는 프런트 표시 상태다. DB 상태·API·SSE 계약에 불필요하게 추가하지 않는다.
- 우선순위: 종료 장면 > 확정 결과 > 질문/이해/되묻기 > 응답 준비 > 듣기 > 대기.
- sessionId+messageId, sessionId+qid, 결과 식별자로 중복 재생을 막는다. 스트리밍 토큰마다 아바타를 key로 재마운트하지 않는다.
- 과거 이벤트 복원과 새 이벤트를 구분하고, 오래된 타이머가 최신 상태를 idle로 덮어쓰지 않게 한다.
- 레이아웃 위치와 캐릭터 동작의 transform을 다른 wrapper로 나눠 충돌을 방지한다. 기존 pose=still과 mood의 우선순위를 점검한다.
- 페이지 이탈·세션 교체·오류·재시도 시 timeout/interval/listener를 정리한다. 보이지 않는 캐릭터의 반복 효과는 중지한다.
- reduced motion에서는 이동·점프·컨페티·반복 호흡을 끄고 정적 표정과 상태 텍스트로 전달한다. animationend가 없어도 다음 단계와 버튼이 작동해야 한다.
- 320/390/768/1440px, 키보드 조작, 세 캐릭터의 가르치기→시험→결과, 중복 SSE·연결 중단·재방문·오류·건너뛰기를 실제 브라우저로 확인한다.
- Google 전용 로그인, 서명 세션, 첫 가입/MyPage 한정 온보딩, LLM 프롬프트·채점·LIFE·학습 복구·졸업시험은 변경하지 않는다.
- 모션 변경을 별도 커밋과 변경 목록으로 정리해 이번 작업만 되돌릴 수 있게 한다.
- 완료 후 정지 화면만 제시하지 말고 상태를 직접 전환하는 모션 미리보기 또는 짧은 녹화를 보여줘. 실제 기능과 연결하지 않은 시연은 시연임을 표시한다.
- main 푸시와 배포는 이번 모션 구현 요청과 별도로 명시적인 요청이 있을 때 진행한다.
