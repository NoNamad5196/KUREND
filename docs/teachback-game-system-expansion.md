# 새내기(TeachBack Campus) — 게임 시스템 확장 기획

## 0. 확장 방향

현재 핵심 학습 루프는 유지한다.

```text
강의자료 업로드
→ 학습 범위 생성
→ 후배에게 가르치기
→ 후배 시험
→ 채점
→ 놓친 부분 확인
→ 되짚기
→ 완료
```

여기에 다음 게임 시스템을 추가한다.

```text
후배 선택
→ ♥ 목숨을 가진 후배와 학습 시작
→ 내가 후배에게 강의
→ 후배 시험
→ 합격/불합격 판정
→ 오답노트 작성 및 복습
→ 반복 학습

        ├─ 계속 실패 → 목숨 감소
        │              ↓
        │          목숨 0
        │              ↓
        │          GAME OVER
        │              ↓
        │         후배가 떠남
        │              ↓
        │        새로운 후배 시작
        │
        └─ 모든 학습 통과
                       ↓
                    졸업
                       ↓
                 Graduation
                       ↓
                새로운 후배 시작
```

핵심 컨셉은 단순히 문제를 맞히는 게임이 아니다.

**“내가 후배를 얼마나 잘 가르쳐서 무사히 졸업시킬 수 있는가?”**

를 게임의 목표로 만든다.

---

# 1. 후배 선택 시스템

기존 KU 외에 남학생, 여학생 캐릭터를 추가한다.

총 3명의 후배가 존재하며 각각 게임 난이도와 시험 방식이 다르다.

## 1-1. 남학생 — EASY

### 성격

- 비교적 이해가 빠름
- 선배의 설명을 잘 따라옴
- 한 번 제대로 설명하면 대부분 기억
- 질문도 비교적 단순함
- 초심자용 캐릭터

### 학습 특성

```text
이해력       ★★★★★
기억력       ★★★★★
되묻기 빈도  ★★☆☆☆
시험 난이도  ★★☆☆☆
```

### 시험

**객관식 중심**

예:

```text
Q. CPU 스케줄링의 목적은 무엇일까요?

① CPU를 사용하지 않도록 한다.
② 여러 프로세스에게 CPU를 효율적으로 배분한다.
③ 모든 프로세스를 동시에 실행한다.
④ 메모리를 초기화한다.
```

### 합격 기준

기본 권장:

```text
60점 이상 = 합격
60점 미만 = 실패
```

---

## 1-2. 여학생 — NORMAL

### 성격

- 설명 이해는 빠른 편
- 제대로 들은 내용은 한 번에 기억
- 단순 암기보다 설명의 의미를 이해하려 함
- 가끔 “왜 그런가요?”와 같은 추가 질문을 함

### 학습 특성

```text
이해력       ★★★★☆
기억력       ★★★★★
되묻기 빈도  ★★★☆☆
시험 난이도  ★★★☆☆
```

### 시험

**서술형 중심**

예:

```text
Q. Round Robin Scheduling이 무엇인지
자신이 이해한 방식으로 설명하세요.
```

AI 후배가 사용자가 가르친 내용만 이용해 답변한다.

### 합격 기준

기본 권장:

```text
70점 이상 = 합격
70점 미만 = 실패
```

---

## 1-3. KU — HARD

기존 캐릭터 KU는 최고 난이도 캐릭터로 사용한다.

### 성격

- 이해를 쉽게 못 함
- 애매한 설명은 잘못 이해할 가능성이 있음
- 중요한 개념은 한 번 설명하는 것만으로 완전히 학습하지 못할 수 있음
- 같은 내용을 다른 방식으로 다시 설명해야 할 수도 있음
- 적극적으로 되묻는다

### 학습 특성

```text
이해력       ★★☆☆☆
기억력       ★★★☆☆
되묻기 빈도  ★★★★★
시험 난이도  ★★★★★
```

### 반복 학습

KU에게는 개념별 **숙련도/이해 카운트**가 존재한다.

예:

```text
Round Robin

1회 설명
[■■□□□]
"음... 대충 알 것 같은데..."

2회 설명
[■■■■□]
"아, 조금 이해되는 것 같아."

3회 설명
[■■■■■]
"이제 알겠어!"
```

모든 개념이 반드시 3회 설명을 요구하는 것은 아니다.

AI가 설명 품질을 평가하여:

```text
매우 명확한 설명
→ 1~2회 만에 이해 가능

보통 설명
→ 2회 필요

애매하거나 부족한 설명
→ 3회 이상 필요
```

처럼 처리한다.

### 시험

**서술형**

단순 정의뿐 아니라 이유, 비교, 응용 문제도 포함할 수 있다.

### 합격 기준

기본 권장:

```text
80점 이상 = 합격
80점 미만 = 실패
```

# 2. 후배 선택 화면

새로운 학습을 시작하기 전:

```text
이번에는 어떤 후배를 졸업시켜볼까요?
```

3개의 Character Card를 보여준다.

```text
┌─────────────────┐
│ 남학생           │
│ EASY             │
│                  │
│ 이해가 빠른 후배 │
│ 객관식 시험      │
│                  │
│ [선택하기]       │
└─────────────────┘

┌─────────────────┐
│ 여학생           │
│ NORMAL           │
│                  │
│ 이해는 빠르지만  │
│ 서술형 시험      │
│                  │
│ [선택하기]       │
└─────────────────┘

┌─────────────────┐
│ KU               │
│ HARD             │
│                  │
│ 이해시키기 어려움│
│ 반복 설명 필요   │
│ 서술형 시험      │
│                  │
│ [선택하기]       │
└─────────────────┘
```

선택한 후배는 **현재 Run이 끝날 때까지 유지한다.**

Run 종료 조건:

```text
GAME OVER
또는
GRADUATION
```

# 3. 목숨 시스템

각 후배에게 목숨이 존재한다.

## 기본값

데모 및 게임성을 고려하면:

```text
MAX_LIVES = 3
```

을 기본값으로 추천한다.

향후 설정에서 5개 모드도 가능하게 한다.

UI:

```text
KU    ♥ ♥ ♥
```

또는

```text
KU
LIFE 3 / 3
♥ ♥ ♥
```

---

# 4. 목숨 감소 조건

목숨은 **문제 하나를 틀릴 때마다 바로 깎지 않는다.**

시험 한 번을 하나의 학습 결과로 본다.

각 캐릭터별 합격점 미달 시:

```text
남학생  < 60점
여학생  < 70점
KU      < 80점
```

→ 목숨 1개 감소.

예:

```text
시험 결과

Score
54 / 100

합격 기준
70점

학습 실패

♥ ♥ ♥
↓
♥ ♥ ♡
```

문구:

```text
후배가 아직 내용을 충분히 이해하지 못했어요.

LIFE -1
```

---

# 5. 목숨 회복

시험에서 **100점**을 받으면:

```text
LIFE +1
```

단:

```text
현재 LIFE < MAX_LIVES
```

일 때만 증가한다.

예:

```text
♥ ♥ ♡

100점!

PERFECT TEACHING

♥ ♥ ♥
```

이미 최대 목숨이면:

```text
♥ ♥ ♥

PERFECT!

이미 체력이 가득 차 있습니다.
```

# 6. 오답노트 시스템

시험 문제를 틀리거나 부분 정답을 받은 경우 해당 문제는 자동으로 **오답노트**에 등록한다.

단순히 AI가 정답을 알려주는 것으로 끝내지 않는다.

사용자가 먼저:

```text
왜 이 문제가 틀렸을까?
```

를 직접 작성한다.

## 6-1. 오답노트 화면

예:

```text
Q2.

Round Robin과 FCFS의 차이를 설명하세요.

────────────────────

후배의 답변

"Round Robin은 먼저 들어온 프로세스를
먼저 실행하는 방식입니다."

────────────────────

결과

✕ WRONG

────────────────────

왜 틀렸을까요?

[                                   ]
[                                   ]
[                                   ]

────────────────────

힌트

내가 가르칠 때
'Time Quantum'에 대한 설명이 부족했습니다.

────────────────────

[오답노트 저장]
```

---

# 7. 오답노트 구성

저장되는 내용:

```text
과목
자료
챕터

문제

후배의 답변

점수

판정
CORRECT / PARTIAL / WRONG

내가 생각한 오답 원인

AI가 분석한 오답 원인

내 설명 중 관련 부분

원본 강의자료 관련 부분

놓친 핵심 개념

작성 날짜
```

---

# 8. 오답 원인 비교

사용자가 먼저 오답 이유를 작성한 뒤 AI 분석을 공개한다.

예:

```text
내 생각

"Round Robin이랑 FCFS를
헷갈리게 설명한 것 같다."

AI 분석

맞아요.

특히 선배가 설명할 때
Round Robin의 핵심인

'Time Quantum'

을 명확하게 설명하지 않았습니다.

그래서 후배가 FCFS와 비슷한 방식으로
기억한 것으로 보입니다.
```

즉,

```text
AI가 정답 알려주기
```

보다

```text
내가 왜 잘못 가르쳤는지 생각
→ AI 분석과 비교
```

하도록 한다.

# 9. 오답 재학습

오답노트 하단에:

```text
[다시 가르치기]
```

버튼을 제공한다.

누르면 해당 Gap과 관련된 개념만 뽑아서 짧은 재학습 세션으로 이동한다.

예:

```text
오늘의 재교육

Round Robin
Time Quantum
Context Switch
```

# 10. 학습자료 업로드 후 「선배용 강의노트」 생성

현재 자료를 업로드하면 목차만 생성하는 것에서 한 단계 추가한다.

자료 분석 완료 후 AI가:

# 선배용 강의노트

를 자동 생성한다.

목적은 **AI 후배에게 가르치기 전에 사용자가 먼저 범위를 공부할 수 있게 하는 것**이다.

---

# 11. 선배용 강의노트 구성

각 챕터마다:

```text
Chapter 03
CPU Scheduling

────────────────────

이번에 가르쳐야 할 것

1. CPU Scheduling이 필요한 이유
2. FCFS
3. SJF
4. Round Robin
5. Time Quantum
6. Context Switching

────────────────────

이것만은 알고 가기

• FCFS는 먼저 도착한 프로세스부터 처리한다.
• Round Robin은 Time Quantum을 사용한다.
• Time Quantum이 너무 짧으면 Context Switch가 증가한다.

────────────────────

헷갈리기 쉬운 부분

FCFS와 Round Robin의 차이

SJF와 SRTF의 차이

────────────────────

후배가 물어볼 수 있는 질문

"왜 그냥 먼저 온 프로세스부터 실행하면 안 돼?"

"Time Quantum은 짧을수록 좋은 거야?"

────────────────────

[학습 시작]
```

---

# 12. 강의노트 다시 보기

한 번 생성된 강의노트는 삭제되지 않는다.

자료 상세 페이지에서 언제든:

```text
[선배용 강의노트 보기]
```

가능.

가르치는 도중에도:

```text
[강의노트 잠깐 보기]
```

버튼을 사용할 수 있다.

단, 사용자가 답을 그대로 복사하는 느낌을 줄이지 않기 위해 별도 Drawer 또는 Modal에서 표시한다.

---

# 13. GAME OVER

현재 후배의 LIFE가:

```text
0
```

이 되는 순간 게임 오버.

학습자료나 사용자의 기록 자체를 삭제하지 않는다.

초기화되는 것은 **현재 후배의 학습 진행 상태**이다.

즉:

유지:

```text
업로드 자료
선배용 강의노트
사용자의 시험 기록
오답노트
과거 세션
통계
```

초기화:

```text
현재 후배
현재 후배의 학습 기억
현재 후배의 챕터 진행도
현재 Run
```

---

# 14. GAME OVER — KU

KU의 목숨이 0이 되면 화면 전환.

배경:

```text
대학교 정문 또는 캠퍼스 길
```

멀리 작은 트럭이 서 있음.

KU가 가방을 들고 트럭 뒤에 올라탄다.

카메라는 멀리서 이를 바라본다.

트럭이 천천히 출발한다.

텍스트:

```text
GAME OVER

어...

KU가 어디 트럭에 타버렸네.

안녕~
다음에 봐~~
```

트럭이 화면 밖으로 사라진다.

잠시 정적.

그 다음:

```text
새로운 후배가 찾아왔어요.
```

→ 후배 선택 화면.

전체 분위기는 **슬프다기보다는 어이없고 웃픈 연출**.

---

# 15. GAME OVER — 남학생

남학생의 LIFE가 0.

캠퍼스 앞으로 군용 두돈반 트럭이 등장한다.

남학생이 군용 가방을 들고 있음.

뒤를 한 번 돌아보고 손을 흔든다.

그리고 두돈반 뒤에 올라탄다.

트럭 출발.

텍스트:

```text
GAME OVER

어라...

남자 후배가 결국 군대로 떠나버렸네.

잘 다녀와...

다음에 보자~~
```

화면 밖으로 사라짐.

이후:

```text
새로운 후배가 찾아왔어요.
```

---

# 16. GAME OVER — 여학생

여학생의 LIFE가 0.

다른 두 캐릭터와 달리 별다른 사건을 보여주지 않는다.

평범한 캠퍼스 배경.

여학생이 멀리 걸어간다.

점점 작아진다.

화면 밖으로 사라진다.

텍스트:

```text
GAME OVER

어라...

여자 후배가 어디로 갔지?

음...

다음에 볼 수 있겠지~
```

몇 초간 빈 캠퍼스.

그리고:

```text
새로운 후배가 찾아왔어요.
```

---

# 17. 새로운 후배

Game Over 뒤에는 데이터를 전부 삭제하지 않는다.

새로운 Run을 생성한다.

```text
새로운 후배가 찾아왔습니다.

이번에는 졸업까지
무사히 가르쳐볼까요?
```

사용자는 다시:

```text
남학생
여학생
KU
```

중 하나를 선택한다.

같은 캐릭터를 다시 선택해도 된다.

---

# 18. 졸업 조건

현재 후배가 해당 학습자료의 필수 챕터를 모두 통과하면 졸업할 수 있다.

권장 조건:

```text
모든 챕터 최소 1회 합격

AND

최종 종합시험 합격
```

종합시험 합격선은 캐릭터별 난이도를 따른다.

```text
남학생   60
여학생   70
KU       80
```

# 19. 최종시험

모든 챕터가 완료되면:

```text
졸업시험에 도전할까요?
```

표시.

졸업시험은 전체 자료에서 문제를 출제한다.

예:

```text
남학생
→ 객관식 5~10문제

여학생
→ 서술형 3~5문제

KU
→ 서술형 + 응용 3~5문제
```

합격하면 Graduation.

불합격하면 일반 시험과 동일하게 LIFE -1.

따라서 졸업시험에서 목숨이 0이 될 수도 있다.

# 20. GRADUATION

졸업 조건을 만족하면 Game Over 대신 Graduation 연출.

캐릭터가:

```text
학사모
졸업 가운
졸업장
```

을 착용한다.

캠퍼스 졸업식 배경.

화면:

```text
GRADUATION

드디어 졸업이다!

축하해~
```

캐릭터가 졸업장을 들고 기뻐함.

가능하면 학사모를 위로 던지는 짧은 애니메이션.

# 26. 게임 시스템 핵심 규칙

## Rule 1

사용자는 문제를 직접 푸는 것이 아니다.

**사용자가 가르친 후배가 시험을 본다.**

이 원칙은 절대 변경하지 않는다.

## Rule 2

후배는 사용자가 가르친 내용 이상을 임의로 알아서는 안 된다.

## Rule 3

난이도가 높다고 단순히 시험 문제가 어려워지는 것만으로 끝내지 않는다.

캐릭터마다:

```text
이해 방식
기억 방식
되묻기 빈도
시험 형식
합격선
```

이 달라야 한다.

## Rule 4

Game Over는 벌점 화면이 아니라 캐릭터 이벤트다.

사용자가:

```text
"아 씨 얘 보내버렸네 ㅋㅋ"
```

라고 느낄 정도의 가벼운 코미디가 목표다.

## Rule 5

실패해도 공부 기록을 삭제하지 않는다.

게임상의 캐릭터 진행만 Reset한다.

# 27. 데이터 구조 확장안

기존 FROZEN 계약은 가능한 한 건드리지 않는다.

신규 기능은 additive 방식으로 추가한다.

예:

```ts
type JuniorCharacter =
  | "MALE_EASY"
  | "FEMALE_NORMAL"
  | "KU_HARD";

interface JuniorRun {
  id: string;
  userId: string;

  character: JuniorCharacter;

  lives: number;
  maxLives: number;

  status:
    | "ACTIVE"
    | "GAME_OVER"
    | "GRADUATED";

  startedAt: string;
  endedAt?: string;
}

interface ChapterProgress {
  runId: string;
  chapterId: string;

  attempts: number;
  bestScore: number;

  cleared: boolean;
}

interface WrongNote {
  id: string;

  sessionId: string;
  qid: string;

  userReason: string;
  aiDiagnosis: string;

  createdAt: string;
}
```

KU가 사용하는 개념 반복 기억은 추가로:

```ts
interface ConceptMastery {
  concept: string;
  exposureCount: number;
  mastery: number; // 0~100
}
```

형태로 관리 가능하다.

# 31. 디자인 톤

전체 UI는 지나치게 게임 UI처럼 만들지 않는다.

기본은 현재 대학 학습 서비스 디자인을 유지한다.

게임 요소는:

```text
LIFE
CLEAR
FAILED
PERFECT
GAME OVER
GRADUATION
캐릭터 이벤트
```

에서 강하게 보여준다.

즉:

```text
평소 = 학습 서비스

시험 결과 / 이벤트 = 게임
```

이라는 대비를 만든다.

# 32. 최종 서비스 메시지

기존:

> 가르쳐야 아는 AI 새내기에게 전공을 가르쳐라.

확장 후:

> **내가 제대로 가르쳐야 이 후배가 졸업한다.**

또는:

> **이번 후배는 졸업시킬 수 있을까?**

사용자가 공부하는 행위를:

```text
내 시험공부
```

가 아니라

```text
후배를 졸업시키는 과정
```

처럼 느끼게 하는 것이 이번 게임 시스템의 핵심이다.
